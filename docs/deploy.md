# Deploying Spigot on Render (SP-040)

`render.yaml` at the repo root is a Render Blueprint for the whole stack. The real deploy happens
after the code freeze from the human's Render account; nothing here has been applied yet.

| Kind | Name | Plan | What |
|---|---|---|---|
| Web | `spigot-api` | starter, 1 instance | API (publisher REST, buyer `/v1`, `/mcp`, gate endpoints, webhooks, in-process jobs) and the web app, served same-origin. Build `npm ci --include=dev && npm run build`; start `npm run migrate && npm start`; health `/api/healthz` |
| Web | `bluebonnet-rentals` | starter, 1 instance | The fictional demo site with `spigot-gate`. 1 GB disk at `/var/data`, `DEMO_DATA_DIR=/var/data/bluebonnet`; health `/healthz` |
| Workflow | `spigot-workflows` | per task (in code) | Render Workflows **stub**: SP-041a registers the crawl / extract tasks, SP-041b adds `payoutRun` and checks it on Render. Unused while `WORKFLOWS_MODE=inproc` |
| Postgres | `spigot-db` | `basic-256mb`, 1 GB, PG 16 | Private network only (`ipAllowList: []`) |
| Env group | `spigot-config` | | Non-secret flags only (table below) |

**Why paid:** free web services sleep, so a judge's first visit to the demo site would wait ~30 s.
Free Postgres expires ~30 days after creation, before judging ends on **Dec 21**. Starter web ×2
(~$7/month each) + `basic-256mb` (~$6/month) + 2 GB of disk is about **$30 for Nov 12 → Dec 21**,
inside the Render hackathon credit. Check the Billing page after the first deploy.

**Migrations** run on every start. The runner is idempotent and holds an advisory lock (SP-002),
so a restart re-applies nothing. A failed migration crash-loops the new deploy; Render keeps the
old instance serving until the new one passes its health check. **Never seed on deploy:**
`npm run seed:demo` is run by hand from the `spigot-api` Shell (SP-035).

## Environment variables

Secrets are `sync: false` in `render.yaml`: Render prompts for them once, when the Blueprint is
first applied, and never reads them from git. Set them by hand afterwards under the service's
**Environment** tab. `scripts/render-blueprint.test.ts` fails if any secret gets a literal value.

|---|---|---|

Keep payouts small (the demo's ~$400 is fine; $2,500+ returned `INSUFFICIENT_FUNDS`).

## Validate the Blueprint (do this early)

1. **Offline** (no account): validate against Render's published schema. From a scratch directory
   outside the repo:
   ```sh
   mkdir -p /tmp/render-schema && cd /tmp/render-schema
   curl -sSfLO https://render.com/schema/render.yaml.json
   npm i ajv@8 ajv-formats@3
   node -e '
     const Ajv=require("ajv/dist/2020").default, f=require("ajv-formats");
     const YAML=require(process.argv[2]+"/node_modules/yaml");
     const doc=YAML.parse(require("fs").readFileSync(process.argv[2]+"/render.yaml","utf8"));
     const ajv=new Ajv({allErrors:true,strict:false}); f(ajv);
     const ok=ajv.validate(require("./render.yaml.json"),doc);
     console.log(ok?"VALID":JSON.stringify(ajv.errors,null,2)); process.exit(ok?0:1)' "$REPO"
   ```
   (`$REPO` = the repo root.) SP-040 ran this against the schema as of Nov 12: valid.
2. `npx vitest run --project unit --maxWorkers=2 scripts/render-blueprint.test.ts`: the rules the
   schema can't check (no secret values, paid plans, auto-deploy off, keys Spigot reads).
3. **With the Render account** (human): `render blueprints validate render.yaml` (Render CLI,
   after `render login`), or Dashboard → **New → Blueprint** → pick the repo and read the preview
   before clicking Apply. Fix anything it reports before the freeze: an error found at 18:00 costs
   recording time.

## First deploy (human, after the freeze)

1. Render Dashboard → **New → Blueprint** → connect `Nemil21/spigot`, branch `main`.
2. Fill the prompted values (tables above). Leave `SPIGOT_GATE_KEY`, `SPIGOT_VERIFY_TOKEN`,
   `PAYPAL_WEBHOOK_ID`, `RENDER_API_KEY` and `RENDER_WORKFLOWS_SERVICE_ID` empty for now. For
   `APP_BASE_URL`, `SPIGOT_API_BASE` and `DEMO_SITE_URL` use the default hosts
   (`https://spigot-api.onrender.com`, `https://bluebonnet-rentals.onrender.com`); if Render gives a
   service a suffixed host, correct them after the first deploy and redeploy.
3. **Apply.** Render creates `spigot-db`, then builds both web services; `spigot-api` migrates on
   start. `spigot-workflows` may fail to start until SP-041a lands: harmless while
   `WORKFLOWS_MODE=inproc`.
4. Check: `node scripts/smoke-deploy.mjs https://<spigot-api> --site https://<bluebonnet-rentals>`.
   Health, the web app and the demo site pass; the gate is still open (no key yet).
5. `spigot-api` → Shell: `npm run seed:demo` (SP-035). Or connect the site by hand in the web app
   (W02/W03) with origin `https://<bluebonnet-rentals host>`.
6. Copy the site's gate key and verify token into `bluebonnet-rentals` → Environment
   (`SPIGOT_GATE_KEY`, `SPIGOT_VERIFY_TOKEN`), then **Manual Deploy**. Verify the site in W03.
7. PayPal webhook: sandbox app → Webhooks → add `https://<spigot-api>/webhooks/paypal` (events
   `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.PAYOUTS-ITEM.*`), paste the id into `PAYPAL_WEBHOOK_ID`,
   Manual Deploy.
8. Approve and publish a dataset (W05/W06), then the strict smoke (below).
9. Workflows (SP-041b, optional for the video): set `RENDER_API_KEY` and
   `RENDER_WORKFLOWS_SERVICE_ID`, then `WORKFLOWS_MODE=workflows` on `spigot-api` only.

## Smoke

```sh
node scripts/smoke-deploy.mjs <api-base> --site <demo-site-url> [--strict]
# with the site's gate key, to fetch the policy too (read from the environment, never printed):
SPIGOT_GATE_KEY=gk_… node scripts/smoke-deploy.mjs <api-base> --site <demo-site-url> --strict
```

Checks: `/api/healthz`, the web app at `/`, `GET /v1/catalog`, `GET /api/gate/policy` (401 without
a key, the policy with one), the demo site's `/healthz`, and one listing page from its sitemap:
a human browser and Googlebot get 200, GPTBot gets the 402 contract (`PAYMENT_REQUIRED`, `Link
rel="payment"`, `Cache-Control: no-store`, datasets, pay with PayPal).

A step whose feature isn't built yet (the API answers "No route for …", or the gate lets GPTBot
through) prints `pending` and doesn't fail; `--strict` turns pending into failure. Use `--strict`
on Render once the site is connected and a dataset is published.

Locally:
```sh
npm run dev:db                                   # shared Postgres; paste DATABASE_URL into .env
npm run migrate && npm run build
npm start &                                      # spigot-api on :3000
PORT=4100 npm start -w @spigot/demo-site &       # demo site on :4100
node scripts/smoke-deploy.mjs http://localhost:3000 --site http://localhost:4100
kill %1 %2
```

## Auto-deploy

**Off on every service** (`autoDeployTrigger: 'off'`). Deploy only with **Manual Deploy → Deploy
latest commit**:

- The recording passes (18:30–23:00 IST Nov 12) must not have a build change mid-take. Under the
  split-freeze plan (INDEX), redeploy by hand after each screen PR merges, between takes.
- After submission the judged build must not change (rules forbid edits after the deadline). Don't
  deploy again until judging ends on Dec 21, except to fix an outage, and say so in the README.

A deploy restarts the demo site (it has a disk, so no zero-downtime deploy): expect a few seconds
of 502. Its data survives (seed is deterministic; mutations are on the disk).
